## Одна платформа. Три способи підключення.

Biointron OS — це інтерфейс доступу до сервісів Biointron для ШІ-агентів, моделей і людей. Він поєднує доступ до сервісів з інструкціями для робочих процесів. План розвитку охоплює замовлення, подані проєктні дані, перебіг виконання та результати.

| Для агентів | Для моделей | Для людей |
| :--- | :--- | :--- |
| Знаходьте та викликайте сервіси через **MCP**. | Працюйте зі **структурованими даними** й документованими інтерфейсами. | Отримуйте доступ до робочих процесів через **інтерактивний інтерфейс**. |
| Поєднуйте виклики інструментів зі Skills для конкретних завдань. | Правила подання даних узгоджуються протягом Beta-фази. | Вебінтерфейс надається окремо від цього репозиторію. |

Цей репозиторій — публічне джерело Skills, інструкцій із підключення, каталогу інструментів і прикладів. Бізнес-сервіси Biointron працюють окремо.

## Початок роботи

### 1 · Підключіть MCP

Отримайте токен доступу до сервісу та необхідні дозволи у свого контактного представника Biointron. У клієнті MCP, який підтримує **Streamable HTTP** та **автентифікацію Bearer**, додайте:

| Налаштування | Значення |
| :--- | :--- |
| Назва | `BiointronOS_MCP` |
| Транспорт | Streamable HTTP |
| URL | `https://mcp-rusta-order-blgdfvompw.cn-shanghai.fcapp.run/mcp` |
| Автентифікація | `Authorization: Bearer <MCP_ACCESS_TOKEN>` |

У клієнтах, які підтримують формат `mcpServers`, об’єднайте цю конфігурацію з наявними налаштуваннями та замініть заповнювач власним токеном:

```json
{
  "mcpServers": {
    "BiointronOS_MCP": {
      "url": "https://mcp-rusta-order-blgdfvompw.cn-shanghai.fcapp.run/mcp",
      "headers": {
        "Authorization": "Bearer <MCP_ACCESS_TOKEN>",
        "START_MCP_TIMEOUT_MS": "60000",
        "RUN_MCP_TIMEOUT_MS": "660000"
      }
    }
  }
}
```

Два заголовки тайм-ауту — це власні параметри наведеної конфігурації: 60000 мс = 60 секунд, а 660000 мс = 11 хвилин. Вони діють лише за підтримки клієнтом або сервісом; додавання їх до `headers` саме по собі не гарантує зміни часу очікування клієнта. Налаштовуйте тайм-аути відповідно до документації свого клієнта.

Докладніше дивіться в [інструкції зі встановлення](../../docs/installation.md#mcp).

### 2 · Додайте Skills

Виберіть опублікований Skill у [каталозі Skills](../../skills/README.md). Завантажте всю його папку, зокрема `references/`, надані скрипти та інші файли, на які він посилається, та помістіть її в каталог Skills вашого агента. Інструкції для Codex і Claude Code наведено в розділі [встановлення Skills](../../docs/installation.md#skills).

Обидва пакети Skills включені та доступні для завантаження. `auto-html-report` локально створює звіти з уже наданого JSON результатів — без облікових даних і підключення MCP. Якщо JSON відсутній, у межах наданого дозволу можна спочатку отримати результати через `get_report_results`, використовуючи підтверджений номер замовлення й чинний JWT поточного клієнта, а потім створити звіт. Одного номера замовлення недостатньо. Biointron Account і App Key використовуються лише за відсутності чинного JWT; надані значення використовуються повторно, а запитуються лише відсутні. Інструкції Skill написані англійською, але звіти й надалі можуть бути багатомовними.

### 3 · Почніть з ознайомлення в режимі лише читання

```text
Перелічи інструменти Biointron MCP, доступні в цьому сеансі, і поясни призначення кожного.
Повідом, які можливості готові до використання, а які ще перебувають у Beta-фазі.
Не створюй і не подавай замовлень.
```

Отримання списку інструментів — це перша перевірка підключення. Для успішного виконання бізнес-операції потрібне також перевірене підключення до відповідної серверної системи.

## Каталог інструментів MCP

| Інструмент | Призначення | Вплив |
| :--- | :--- | :--- |
| `get_order_input_requirements` | За замовчуванням збирає незалежні запитання пакетами; перед записом перевіряє всі дані етапу разом через `mode="validate"`. Бізнес-JWT не потрібен. | Лише читання |
| `search_order_antigens` | Шукає в каталозі за ключовим словом і повертає реальні товари та варіанти разом із даними для завантаження наступних сторінок. | Лише читання |
| `order_design_preflight` | Перевіряє право компанії на обслуговування та доступні дослідження. | Лише читання |
| `start_order_design` | Передає наданий XLSX і очікує підтвердження збереження проєкту. | Записує бізнес-дані |
| `get_order_design_result` | За вибором клієнта отримує лише для читання та передає справжній HTML збереженого проєкту. | Лише читання |
| `add_order_to_cart` | Додає до кошика проєкт із підтвердженим збереженням. | Записує бізнес-дані |
| `end_order_workflow` | Запропонувати клієнту видалити локальний контекст без відкликання підпису чи скасування замовлення. | Лише інструкція клієнту |
| `get_order_cart` | Читає кошик замовлень. | Лише читання |
| `calculate_order_price` | Отримує розрахунок вартості вибраних замовлень. | Лише читання |
| `submit_verified_order` | Повторно перевіряє цінову пропозицію й надсилає вибрані замовлення для підтвердження людиною. | Записує бізнес-дані |
| `get_report_results` | Отримати результати наявних звітів у форматі JSON. | Лише читання |

У поточній реалізації MCP зареєстровано 11 інструментів: 10 потребують бізнес-JWT поточного клієнта; `get_order_input_requirements` працює локально без цього JWT. Розгортання та готовність бізнес-процесів до роботи від початку до кінця ще належить перевірити. Дивіться [сигнатури, стан і обмеження](../../docs/tool-catalog.md).

## Skills

| Skill | Призначення | Стан публікації |
| :--- | :--- | :--- |
| [Проєктування замовлень · `order-design`](../../skills/order_design/SKILL.md) | Пояснює пакети послуг, збирає дані групами, допомагає вибрати товари з каталогу, пропонує перегляд HTML після збереження проєкту та супроводжує кошик, цінову пропозицію й подання на підтвердження людиною. | Включено · Доступно для завантаження |
| [Звіт за результатами · `auto-html-report`](../../skills/auto_html_report/SKILL.md) | Створює автономні багатомовні HTML-звіти зі зведеною таблицею, діаграмами й доступними зображеннями з наданого JSON результатів або даних, отриманих авторизованим запитом. | Включено · Доступно для завантаження |

Подання замовлення не означає початку виробництва або завершення експерименту. Виробництво починається лише після підтвердження Biointron.

MCP надає операції; Skills описують, як агент використовує їх у межах завдання. Встановлення Skill не надає доступу до сервісу й не реєструє MCP автоматично. [Переглянути каталог →](../../skills/README.md)

## Beta Playground

Biointron OS представлено як тестове середовище Beta. Деякі підключення можуть бути ще недоступними. Повідомляйте фактичний результат кожного кроку; успішна HTTP-відповідь або видима назва інструмента не доводять, що бізнес-операцію завершено.

Створення та подання замовлень потребують дозволу користувача. Якщо під час запису сплив час очікування, перевірте стан наявного замовлення, перш ніж повторювати спробу. Щодо доступу або недоступної функції зверніться до представника Biointron, який надав ваш обліковий запис.

## Поширені запитання

<details>
<summary><strong>Чи потрібні мені одночасно MCP і Skills?</strong></summary>

MCP надає інструменти, які можна викликати. Skills додають інструкції для робочих процесів і можуть мати власні залежності. Дотримуйтеся вимог кожного опублікованого Skill; саме лише завантаження Skill не підключає сервіс.

</details>

<details>
<summary><strong>Чи означає наявність інструмента в списку, що він готовий до бізнес-використання?</strong></summary>

Ні. Виявлення інструмента підтверджує його реєстрацію. Також потрібно перевірити налаштування серверної системи, доступ до облікового запису й запитану операцію. Каталог відображає цю відмінність.

</details>

<details>
<summary><strong>Де розташовані сервер і реалізація бізнес-логіки?</strong></summary>

Цей репозиторій поширює публічні матеріали з інтеграції та Skills. Розміщений сервіс і приватна реалізація бізнес-логіки підтримуються окремо.

</details>
