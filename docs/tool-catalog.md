# MCP tool catalog / MCP 工具目录

[Home](../README.md) · [中文首页](readme/README.zh-CN.md) · [Installation / 安装](installation.md) · [API notes / API 说明](api.md)

Biointron OS is a **Beta / Playground** integration. This local version provides **11 tools, 5 resources and 2 prompts**: ten customer-related business/workflow tools require JWT, and one local input-requirements tool does not. The existing MCP service is deployed on Alibaba Cloud FC; discovery and both Skills' resources/prompts were verified on 2026-11-01. This update has not been deployed; no live business request or integration test was run. Full business workflows still require live validation; the connected server's returned schemas govern that deployment.

Biointron OS 当前为 **Beta / Playground** 接入版本。本地版本提供 **11 个工具、5 个资源、2 个提示词**：十个客户业务或续办工具需要 JWT，一个本地输入说明工具无需业务 JWT。现有 MCP 已部署到阿里云 FC，工具发现及两个 Skill 的资源、提示词曾于 2026-11-01 通过验证；本次更新尚未部署，未调用真实业务或执行联调测试。完整业务流程仍需真实联调，实际云端参数以连接后返回的 schema 为准。

These local tool and Skill changes must be published to the existing cloud service, then refreshed in the client. The earlier cloud verification does not confirm that this later update is already live.

It returns `status=collecting|collected`, `validation_deferred=true`, `write_performed=false`, and a batch of independent questions. `collected` means the known branch has been collected, not that input is valid or a write is authorized. Ask routing decisions (package, Customized sample form, antigen source) separately before their dependent fields. Then invoke the returned `interaction.native_question.questions` in one native call for independent text and choice fields, using the selected language. Merge the whole batch before requesting the next branch or batch; do not call MCP, the model or full validation after every field. CLI prompts through the same batch sequentially without model/MCP round trips, rule rereads or business validation inside the batch. Missing or blank routing answers still need questions. Preserve real `false`, `0` and explicitly supplied `[]`; never invent defaults. Collection does not perform full business validation or scan XLSX contents. Immediately before an actual design or cart write, call `get_order_input_requirements(..., mode="validate", language=language)` with all collected inputs. Validate the whole stage once; on `status=needs_input`, explain all discovered issues and invoke its native correction batch, preserving valid answers. Revalidate after the correction batch, not after each field. `status=ready` confirms local validity only. Compact validation retains all discovered issues and the question batch; use `detail="full"` only when a complete schema or diagnostic report is needed. Actual write-entry guards remain intact: authentication, file transport limits, company eligibility, live catalog and saved-context checks still precede the relevant API call. Keep credentials in client state; account, App Key and JWT never enter `supplied` or business DTOs. Collection and validation do not authorize a write. Reuse the current language, valid JWT and catalog candidates. Do not insert planning, recaps, tool discovery, reconnection or repeated authentication between questions. Design `supplied` contains `data`, `filename`, `file_base64`; cart contains `cart_data`. Omit unknown fields. Client-only workbook paths must be converted locally, never sent as Base64 or remote-readable paths.

`get_order_input_requirements(stage, supplied=None, language=language, detail="compact", mode="collect")` 默认只收集资料：返回 `status=collecting|collected`、`validation_deferred=true`、`write_performed=false` 及当前可独立填写的问题批次。`collected` 仅表示本轮资料已收集，不表示输入正确、已获授权或可写入。套餐、Customized 样本形式、抗原来源等决定后续分支的问题先单独选择；分支确定后，将独立文本及选择题放在同一次 `interaction.native_question.questions` 中实际调用原生工具。合并整批真实答案后再推进下一分支或批次，不对每个字段重新调用 MCP、模型或完整校验。CLI 顺序询问同一批字段，批内不回到模型、不重读规则、不调用输入说明或业务校验。缺失或空白的分支答案仍需询问；保留 `false`、`0` 和客户明确给出的 `[]`，不补默认值。收集阶段不运行完整业务校验或扫描 XLSX。 资料收齐、准备实际设计或购物车写入时，显式调用 `get_order_input_requirements(..., mode="validate", language=language)`，一次检查本阶段全部资料。`status=needs_input` 时汇总全部已发现问题，并用返回的原生问题批次收集修正；保留其他有效答案，整批修改后再校验。`status=ready` 仅表示本地检查通过。`detail="compact"` 保留当前动作、问题批次及全部校验问题；仅需完整 schema 与诊断时用 `detail="full"`。实际写入入口的完整保护保留，认证、文件传输限制、公司权限、产品目录与签名上下文等检查均须在相应 API 调用前通过。凭据只留客户端，App Key、账号和 JWT 不进入 `supplied` 或业务 DTO；收集或校验完成均不新增写入授权。 设计 `supplied` 为 `data`、`filename`、`file_base64`，购物车为 `cart_data`；未知字段省略，文件路径仅在客户端转换。

Across all branches, collect a whole independent-field batch before advancing; no per-field MCP/model or validation round trips. Reuse credentials and avoid plans, recaps, discovery, bridges, reconnects or rule rereads inside a batch. Actual design execution counts the original workbook once, best-effort; collection does not scan XLSX. Transfer checks and pre-write business/permission guards remain. Catalog lookup remains real: one call-local HTTP client reads the first page, then up to four known pages concurrently, awaits every read and merges in page order. Five-page/50-record limits, deduplication, byte caps, partial-error/continuation handling, customer isolation and no automatic retries remain. End-to-end timing was not measured; no fixed response time is promised. See [API details](api.md#local-input-requirements--本地输入说明).

所有分支按独立问题批次收集后推进，批内不逐字段调用 MCP/模型或校验。复用有效凭据，不插入计划、复述、工具发现、桥接、重连或规则重读。实际设计执行才对原文件尽力统计一次；收集不扫描 XLSX，传输检查及写入前业务/权限保护保留。产品库仍真实查询：首个请求页确认范围后，同一次调用客户端并行读取后续最多 4 页，等待全部读取后按页序合并。5 页/每页 50 条、去重、大小上限、部分失败续查及客户隔离均保留，不自动重试。未实测端到端耗时，不承诺固定秒数；详见 [API 说明](api.md#local-input-requirements--本地输入说明)。

Verified receipt identity cannot be overridden. `shippingRequired=false` removes an address binding and is not a default; `true` requires an address already bound through the website. The current JSON-only contract was checked against the test OpenAPI and web client on 2026-11-03; see the [workflow reference](../skills/order_design/references/workflow.md). Deploy the matching backend before using this new tool schema; documentation updates do not update FC.

`add_order_to_cart` 另需 `cart_data`：真实设计 `projectNo`、用户明确选择的布尔值 `shippingRequired`、1–3 个 `antigens`，以及可选的单数字符串 `positiveControl`。订单身份来自验签凭证，不能覆盖。`shippingRequired=false` 会解绑地址，不能默认使用；`true` 需要网页已有地址绑定。2026-11-03 已对照测试环境 OpenAPI 与网页核对 JSON-only 契约，详见[工作流参考](../skills/order_design/references/workflow.md)。使用新 schema 前需同步后端；更新文档不会部署 FC。

Start with package introductions and selection. No separate product page, supplier answer or missing product link is required. External-link/manual modes authenticate before submission. Load `order_design(phase="execute", language=language)` once before design/cart/quote/submission operations, not before library search: default `detail="compact"` provides concise execution rules and connection information; `detail="full"` retains complete references for specific diagnostics. Keep and return the full original signed `workflow_context` with the original JWT supplied separately. During compaction or handoff, retain the context verbatim per secure credential reference and order, plus outer phase/cart fields/authorization/unknown outcomes. No server-side copy can recover lost proof. Report retrieval remains a separate read-only tool; business fields follow the Skill reference.

除本地输入说明外，十个工具（包括 `get_order_design_result`、`search_order_antigens` 和 `end_order_workflow`）每次都须提供当前客户原始 JWT 到 `business_token`，不加 `Bearer`；本地输入说明工具不需要业务 JWT，但 MCP 连接仍需要入口凭据。缺少时不复用服务端或上一客户的凭据；不要回显，客户端可能保存工具调用历史。详见 [API 文档](api.md#credentials--凭据)。

开场先介绍套餐并选择。产品库分支依据本地输入工具的 `catalog_auth` 复用有效 JWT，或补齐 Biointron Account 和 App Key 并兑换，再通过原生文本弹窗或 CLI 输入关键词。调用 `search_order_antigens` 展示真实货号/规格，支持翻页，无结果时换词；保留选项的 `cart_data`，不要求独立产品页面、供应商回答或缺失链接。外部链接和手动资料仍在提交前认证。`order_design(phase="execute", language=language)` 在设计、购物车、报价或提交前只加载一次，不在产品库查询前加载；默认 `detail="compact"` 提供精简执行规则及连接信息，`detail="full"` 保留完整参考供具体排查。完整签名 `workflow_context` 必须原样保留并回传，JWT 单独提供；压缩或交接时按凭据安全引用及订单分别保留，并在外层记录阶段、购物车资料、授权和未知状态。服务端没有副本，丢失就停止。报告查询仍是独立只读工具，业务字段按 Skill 参考。

Signed continuation remains bound to the original JWT, API environment and one-hour validity. It is carried by the AI, not a Redis cache. Ending returns `discard_context` / `server_revoked=false` / `client_action=delete_local_context` / `business_order_cancelled=false`; it cannot revoke other copies or cancel a real order. No shared deduplication or atomic claim is provided. Do not auto-retry or concurrently write the same order; lost/expired proof cannot be reissued.

签名上下文由 AI 携带，绑定原 JWT、API 环境和一小时有效期，没有 Redis 依赖。结束返回 `discard_context`、`server_revoked=false`、`client_action=delete_local_context`、`business_order_cancelled=false`，不能撤销其他副本或取消真实订单。没有共享去重/原子领取；不自动重试或并发写同单，丢失/过期不能补发。

## Discover tools / 获取工具列表

After the MCP client has completed initialization and sent `notifications/initialized`, it can send the illustrative [tools/list request](../examples/tools-list.request.json). Let the client handle the negotiated protocol version and HTTP transport headers. This JSON is a request body, not a complete connection configuration.

MCP 客户端完成初始化并发送 `notifications/initialized` 后，可发送 [tools/list 请求示例](../examples/tools-list.request.json)。协议版本协商和 HTTP 请求头由客户端处理；此 JSON 仅为请求体，不是完整连接配置。

Inspect the returned schemas before invoking tools. Listing tools does not create an order. Design submission, adding to the cart and submitting selected orders change business data; invoke them only within the user's authorized scope. If a write result is uncertain, retain known identifiers and check the existing state before any further write.

调用前查看实际返回的 schema。列出工具不会创建订单；设计提交、加入购物车和提交选定订单会修改业务数据，只能在用户授权范围内使用。写操作结果不确定时，保留已知标识，先核查已有状态再继续写入。

The order Skill batches independent questions, validates completed design/cart inputs before writes, and asks whether to deliver the actual saved-design HTML before cart collection. The report Skill separately creates HTML from existing experimental result JSON. Final order submission requires the customer's confirmation of the exact orders, authoritative quote/discount, and readiness of PO and real company information. `submit_verified_order` submits for Biointron's human confirmation; acceptance is not payment, production confirmation, experimental completion, or result availability.
